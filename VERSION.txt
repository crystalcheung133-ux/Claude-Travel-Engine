Release: Stage3.2H-PORT1-E2B-STORAGE-RESET-ISOLATION
Engine baseline: Stage3.2H-PORT1-E2A.1-IDENTITY-AUTHORITY-CI-REPRODUCIBILITY
Release date: 2026-08-03
Status: E2B implementation candidate; E2C/E2D/E2E not started

Stage E2B introduces trip-scoped storage and reset isolation.

Changes:
- Every Engine-owned localStorage key now follows travel-engine.<tripId>.<module>.v1.
- Admin unlock and booking-reopen session state are trip-scoped.
- Pending moment-photo IndexedDB is named per trip.
- A one-time migration moves eligible legacy NZ state into the NZ namespace only.
- Expenses, Moments, checklist, selected party, itinerary overrides and generation state are preserved where safe.
- Admin unlock/mode, stale sync caches and navigation context are discarded as unsafe.
- Booking overrides and Complete Trip state are preserved in namespaced quarantine rather than silently applied.
- Reset Trip Data clears the active trip namespace by prefix and cannot clear another trip.
- Runtime files no longer own legacy global storage-key fallbacks.
- E2B adds namespace, migration, reset and runtime-ownership CI gates.

Known remaining work:
- E2C: navigation authority and duplicated renderer cleanup.
- E2D: service-worker update-trigger and cache isolation architecture.
- E2E: complete real-browser cross-trip, reset, offline and mobile acceptance.

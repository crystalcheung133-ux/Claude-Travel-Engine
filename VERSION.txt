Stage E2A.1 completes the narrow packaging reproducibility and identity-authority
work identified by the independent E2A deliverable audit.

Changes in E2A.1:
- Removed the external jsdom dependency from the party-rendering test. The CI
  suite is now self-contained and includes a lockfile with zero external npm
  packages, so a clean extraction can run `npm ci` deterministically without
  hidden preinstalled modules.
- Enforced trip-failure-runtime.js as the single production definition of the
  visible `No Trip Loaded` text. Runtime consumers use
  TRIP_FAILURE.NO_TRIP_LOADED_TEXT; if that module is unavailable they fail
  neutrally with empty identity output rather than inventing trip content.
- Neutralised complete-runtime.js's executable Lee fallback to `the trip admin`
  without changing Complete Trip state, permissions, confirmation flow,
  lifecycle logic, storage, reopen behaviour, or UI.
- Added E2A.1 identity-authority and clean-room packaging gates.
- Recomputed reports, authoritative diff, production manifest and checksums.

Stage E2A features retained:
- memory.html party controls use shared config-owned party rendering hooks.
- offline identity is config-driven with a neutral no-trip state.
- index.html has a trip-neutral pre-JS first paint.
- manifest.webmanifest is generated from Trip/Theme/Asset config.
- NZ sync/party failure fallbacks were removed from Engine runtime files.
- duplicated static mini-menu NZ subtitles were neutralised.

Known remaining Stage E2 work:
- E2B: storage namespace migration and Reset isolation.
- E2C: Guide/Trip navigation authority and duplicated renderer cleanup.
- E2D: service-worker update-trigger and cache isolation architecture.
- E2E: real-browser portability, navigation, offline, desktop and mobile gates.

No Japan generation, Importer work, storage-key changes, navigation redesign,
Supabase schema changes, Export format changes, or visible UI redesign were
performed in E2A.1.
